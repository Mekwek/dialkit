# DialKit 2.0 evaluation

This is a local refactor for evaluation against `c649f57`. Package version metadata remains `1.4.4`. Nothing has been staged, committed, pushed, or published.

## What changed

- **One config compiler.** Controls, defaults, transition modes, and the control lookup index are built during one traversal. The separate default/mode/index traversals and duplicate type guards are gone. Svelte uses the store's control classification too.
- **One renderer per framework.** Solid and Vue panels use their existing `ControlRenderer`, as React and Svelte already did. This also fixes missing action buttons inside Solid folders.
- **Less work for value updates.** Lookups use the compiled index. Unchanged scalar values and equivalent pad coordinates skip snapshot copies, persistence, and notifications. Changed batches still notify once. Base and active-preset saves retain their separate behavior.
- **Consistent numeric values.** Sliders, shortcuts, and restored store values share rounding logic. Fractional minima, scientific-notation steps, and partial final steps remain precise. All four slider implementations display enough decimal places for their range.
- **Simpler Vue reactivity.** Removed mirrored config/options refs and their watcher chains. External store snapshots use a shallow ref. Reactive configuration changes and the latest action callback still work.
- **Safer persistence.** Malformed JSON, invalid preset records, missing active presets, and invalid transition modes recover to usable state. `presets: false` restores only values; `persist: false` stops subsequent storage writes.
- **Lifecycle fixes.** Rejected configs do not leave extra registrations. React sliders recover from cancelled/lost pointer capture, stop their active snap animation on unmount, and use the current step in drag callbacks.
- **Shared copy output.** Every panel uses the same instruction builder. Copying excludes internal `.__mode` keys. Success feedback follows a successful clipboard write, and copy timers are cleaned up.
- **Removed generated source declarations.** `icons` and `shortcut-utils` declaration files/maps are no longer retained beside source; the build still emits declarations in `dist`.

## What stayed

All existing framework entry exports remain. The store entry adds `isLeafConfigValue` for the packaged Svelte adapter. No dependencies were added.

The distinct default/base/preset states remain because they implement different user operations. Stable immutable snapshots remain necessary for external-store subscriptions. Preset operations still create a snapshot when metadata changes so existing subscribers refresh. Framework-specific lifecycle and animation adapters remain; combining those would introduce more indirection than it removes. The shared pad and easing controllers retain their pointer, keyboard, reset, and fitting behavior.

## Measurements

Node `v25.8.1`, median of seven samples after warmup, comparing the original store with this refactor on the same machine. Each update scenario executes 5,000 writes to the last control in a nested panel. These are store timings, not browser FPS or an application-wide speedup.

| Controls | Changed writes, before | Changed writes, after | Unchanged writes, before | Unchanged writes, after |
| --- | ---: | ---: | ---: | ---: |
| 25 | 1.19 ms | 0.87 ms | 0.97 ms | 0.67 ms |
| 250 | 4.54 ms | 1.74 ms | 4.43 ms | 0.61 ms |
| 1,000 | 18.87 ms | 3.82 ms | 18.77 ms | 0.68 ms |

At 1,000 controls, 100 registration/unregistration cycles changed from 82.78 ms to 79.34 ms. The largest benefit is value updates in larger panels and eliminating repeated unchanged writes. Tests separately verify that unchanged writes cause zero storage writes and zero notifications.

Reproduce the current timings with:

```sh
node --import tsx scripts/benchmark-store.mjs
```

The script also accepts a path to another checkout's `src/store/DialStore.ts` for comparison.

## Validation

- `npm test`: **125 passed**, up from 111. Coverage includes config defaults, shared registrations, remounts, rejected registrations, snapshot stability, presets, malformed persistence, shortcuts, numeric precision, and all four framework controllers.
- `npm run typecheck`: passes for React, Solid, Vue, and Svelte.
- `npm run build`: passes, including Svelte packaging.
- All 20 package export targets exist; relative imports resolve in the extracted npm tarball. React ESM/CommonJS, Vue, store, and timeline runtime imports succeed.
- Public export-name comparison found no removals in the React, Solid, Vue, Svelte, store, or timeline entries.
- Browser checks used the compiled package in React, Solid, Vue, and Svelte: numeric/text edits, pad coordinates, easing keyboard edits, nested actions, toggles, presets, and copy output.
- Additional browser checks covered image selection, color editing, select navigation, slider numeric text entry and repeated dragging, pad dragging/reset, dark/light themes, easing handle dragging, spring mode changes, multi-panel collapse/drag/reopen, and timeline pointer scrubbing/replay.
- `git diff --check`: passes.

The current Svelte check reports **57 warnings in nine files**, exactly matching the untouched baseline. The React/Motion preset menu emits a `ref` warning with the installed dependency versions; it was also reproduced against the original source. These warnings have not been suppressed or presented as new regressions.
